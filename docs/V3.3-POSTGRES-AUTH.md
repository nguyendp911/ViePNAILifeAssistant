# ViePN AI Life V3.3: PostgreSQL authentication

## Changes

- `DATABASE_URL` selects PostgreSQL instead of development JSON account stores.
- `POST /v1/auth/register`: username, password (at least 12 UTF-8 bytes), displayName; returns a random bearer session token.
- `POST /v1/auth/login`: username, password; returns a 7-day session.
- `POST /v1/auth/logout`: revokes current session token.
- `GET /v1/me`: identifies the session owner.
- All preexisting `/v1/*` data routes use session-resolved `user_id` for reading and writing.
- Account-scoped state stored as JSONB in PostgreSQL (`viepn_state`). This is a migration step, **not** a fully normalized data model.
- Passwords are stored as salted scrypt hashes; session tokens only as SHA-256 digests.
- Five consecutive login failures lock the account for 15 minutes. Registration/login should additionally be protected by reverse-proxy IP throttling and bot defenses before public use.

## Deploy

1. Provision PostgreSQL, create a database and a restricted application role.
2. Set `DATABASE_URL=postgresql://...` as a host secret, never check it into Git.
3. Set `PGSSL=require` and the appropriate trusted CA certificates when using cloud PostgreSQL.
4. From `gateway`: `npm ci` (or `npm install` for initial install), `npm test`, `npm run check`, and `npm start`.
5. Place the HTTP gateway behind HTTPS reverse proxy, terminate TLS, and restrict database network access.
6. Register/login on iOS Security Center; bearer session stays in iOS Keychain.

## Security and migration limitations

- Existing JSON account data is **not** imported automatically into PostgreSQL; migration is separate and requires identity mapping/backup.
- In-memory account state uses last-writer-wins on multiple server instances. Deploy **one gateway instance** until versioned atomic update or normalized per-row writes are implemented.
- This version has short-lived (7-day) bearer sessions but no refresh tokens, email verification, forgot-password, MFA, or server-side user-data deletion endpoint.
- App data is not end-to-end encrypted; the gateway can read plaintext in JSONB. Protect backups and audit access.
- Account names are simple identifiers, not verified email addresses.
- Before App Store distribution, implement privacy policy, account deletion in app, retention, observability, throttling, production DB migration and device testing.
