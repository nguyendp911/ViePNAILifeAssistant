# ViePN AI Life V3.0 – Engineering continuation

## Delivered in this iteration

1. `POST /v1/workflows/preview`: validate a structured user-authored note/task/memory proposal. The response contains `executed:false` and `requiresApproval:true`, and does **not** save or execute anything.
2. `POST /v1/workflows/ai-preview`: when an AI model is configured on the gateway, turn a natural-language request into a JSON proposal using an explicitly bounded allowlist (create note / create task only), then revalidate every field. The user still creates and approves workflow steps individually. If the provider is not configured, this endpoint returns HTTP 503. Never treat the model response as executable code.
3. `PATCH /v1/tasks/:id`: update the task's completed state, strictly requiring a boolean.
4. `GET /v1/export`: export selected personal data (tasks, memories, notes, profiles, automations, workflows) in JSON. Does not include API keys or the gateway token. Handle the export as sensitive user data, since the files themselves may contain personal details.
5. Accent-insensitive Vietnamese memory keyword search with relevance ranking (not semantic embedding search).
6. SwiftUI workflow preview, AI draft preview, task completion toggle and privacy export via native Share Sheet.
7. Unit and integration tests for these features.

## V3.0 scope still pending

- Real multi-tenant authentication and authorisation with user-level data isolation, rate limiting, audit controls and encrypted managed database.
- Full Share Extension and cross-app import pipeline.
- Semantic memory embeddings, vector search and privacy controls for hosted inference.
- Real third-party calendar/email integrations with OAuth 2.0 (no third-party account read/write is available today).
- Production deployment, CI typecheck verification, iOS device testing and signed release.

**Important:** The current one-token, JSON-file gateway must be run as a one-user development instance only, behind HTTPS with a reverse proxy. Do not expose it to the general public or reuse one token between different users.
