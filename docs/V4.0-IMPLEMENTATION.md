# ViePN AI Life Assistant V4.0 — implementation and release gates

Date: 2026-11-13. Built on the exact V3.6 source directory and retains the five-tab Premium SwiftUI UI.

## V3.7: semantic retrieval (implemented, optional)

- `gateway/src/semantic.ts`: opt-in server-side embedding provider with HTTPS OpenAI-compatible embeddings endpoint. User explicitly triggers indexing; backend stores vectors in the authenticated tenant's state. Indexes up to 20 chunks per API call. Cached by document content SHA-256, chunk ID and model. Old entries are pruned on rebuild. Dimensionality and finite values checked.
- `POST /v1/semantic/index`: explicit user action; sends chunks to selected third-party embedding provider. Requires server-side env values. No implicit uploads on document save.
- `POST /v1/semantic/search` with `{ "query": "..." }`: true hybrid vector + lexical reciprocal-rank fusion when provider configured, lexical fallback otherwise. Returns `mode` indicating actual method. `GET /v1/semantic/status` reports counts.
- `KnowledgeView.swift`: status, explicit consent alert, indexing button, citation cards. No claims that vector search operates without a configured provider or index.

## V3.8: recoverable manual workflows

- `WorkflowStatus` and `StepStatus` support `failed` when local execution validation throws.
- `POST /v1/workflows/:id/steps/:stepId/retry` reopens a failed step for *fresh manual approval*. Max three retries. It never executes the step, silently repeats network operations or bypasses approval.
- Action Center shows failed workflows and manual reopen controls. All current steps are local create task/note/memory only. External-action idempotency needs separate design before expansion.

## V3.9: snapshot sync groundwork

- `GET /v1/sync` returns authenticated tenant-scoped snapshot plus monotonically incrementing revision and ETag. Optional `If-None-Match` returns 304. `serverRevision` and `synchronizeSnapshot()` in SwiftUI expose it; foreground sync can load a consistent snapshot instead of multiple disparate requests.
- **Not implemented:** encrypted offline mutation queue, two-way conflict resolution and push notifications. Revision is currently per-process/tenant persistence; transactions and multi-worker coordination must be moved into Postgres to achieve production guarantees. A snapshot may still be raced by concurrent writes, especially across instances. This is a read-sync foundation, not full multi-device synchronization.

## Suggested macOS/GitHub build

1. Create a private GitHub repository, push this source tree, enable Actions.
2. Add no secrets to Git history. Configure hosted HTTPS gateway, PostgreSQL with migrations and backups, encryption secret for Google tokens, AI providers.
3. Run `gateway.yml` typecheck and tests, resolve all CI failures.
4. Run `ios.yml` unsigned build; then provision app AND share extension with compatible App Groups and bundle IDs, sign with authorized Apple profiles and test on iPhone.
5. Run real provider OAuth, security, accessibility, network failure, iCloud/Keychain and privacy-deletion tests; only then consider TestFlight.

## Privacy / compliance

- Embedded model calls and vector embeddings use third-party providers, subject to user consent and privacy notices.
- Secure token storage on iOS Keychain; never place upstream API secrets in IPA.
- JSON legacy tenancy is only for local prototype. In production disable fallback token mode, use PostgreSQL and independent audit logs, account deletion, rate limits, encrypted backups and secret rotation.
- New AI functions never send mail or modify calendars. Google integrations remain read-only.
